## 🛑 Warnings for every audit round

1. **`run-all.sh` green ≠ no bugs.** Green proves only that *measured* bugs didn't return. The same bug returning through
   several doors = broken **structure**: count **identities** (sets) instead of **numbers**. Always ask "does this number
   have an identity?"
2. **Bugs live in gaps tools don't watch**: stubs accepting everything (fake SDK never rejects like real rules) · states
   never entered (ledger smaller than the delta · stale local view · a `fetch` that **hangs** · a promise resolving
   **after** the ceiling) · seams between two files (writer locked, reader locked, nobody checks they agree).
3. **Ask "what is *not yet* measured?"**, not "which checker is red?". Methods: fake SDK in **real-rules reject mode** ·
   dependencies in new failure modes (hang · slow success · absent) · fuzz outside the default seed range:
   `FUZZ_RUN0=100 FUZZ_RUNS=14 FUZZ_OPS=50 node audit-tools/revenue-fuzz-test.js` (deeper runs find **new** classes;
   they don't protect old ones).
4. **Review deleted lines in every fix**: `git diff "$BASE_REF" -- ZoeW/src ZoeW/public ZoeKeyGen | grep '^-'` — **an
   unexplained deletion is a regression** (step 1 of 6 of the impact verification, Runbook step 3).
5. **Don't change verified areas on suspicion** (Forbidden zone). **Measurement is evidence, reading code is not.**

## ⛔ Forbidden zone — PTR · history-panel motion · scrolling

- Verified on **real iPhone and Android**. ⛔ Never "fix" on suspicion, code reading or WebKit theory. The right fix for
  snap fighting motion is **pausing snap**, never removing motion.
- Green `run-all.sh` proves only the scenarios run. Guards: `gesture-test.js` · `panel-motion-test.js` ·
  `ios-panel-glide-test.js` · `panel-snap-ownership-test.js` · `phone-search-swipe-test.js`.
- Change only on a **real user report** (video or precise description). If you must: read the 5-point table below,
  **measure** iOS vs Android directly, and test on **real devices of both** before merge.

## Accepted by design — don't report as bugs

- **Users can write revenue/pickup numbers directly** (no trusted backend ➜ no delta or aggregate validation).
- **"Inspect element" protection can't be hardened** (`devtools-guard` is an obstacle, not protection) ⛔ don't try.
- **`zto-import/google-sheets-api/Code.gs` is a template** — repo edits don't change the deployed script (paste into
  script.google.com and deploy a new version by hand).
- **Netlify Base directory lives in the UI**: `zoew` ➜ **`ZoeW`** · `zoekeygen` ➜ **`ZoeKeyGen`** (**case-sensitive**).
- **Clearing site data loses License `seenMax`** — grants nothing without the server (`activate()` needs
  `checkOnline().ok === true`).

⛔ The first four are intentional 📝 acceptances — don't build tools for them unasked.

# 💰 Core business rule — "Delete" vs "Remove"

- **Delete (លុប)** = delete the whole parcel. **Never touches** `zoew_daily_revenue_cod_dod` /
  `zoew_monthly_revenue_cod_dod` in any direction. Idempotent by design.
- **Remove (ដក)** = remove one barcode (or the 7-day cleanup): **deducts** its cod/dod at once, **adds back** on restore,
  deducts again if removed again. Tracked by `isDeducted`.

Odd revenue ➜ first decide which path it is (`isFromDeletion`; trash item has 1 barcode or the full set).

## "Revenue" = value of parcels **picked up**

```
ledger = (picked up) + (waiting, < 7 days) + (deleted by hand)
```

Uncollected parcels ➜ `claimAndCleanupItem('abandon')` ➜ `isDeducted: true` ➜ deducted ➜ purged in 2 days
(`EXPIRED_TRASH_RETENTION_MS`); they return to the central branch and don't stay in our system.

- Both stats screens show **"ចំណូល (យករួច)"**, never the raw ledger, plus total parcel value as a separate row.
- One formula: `collectedValueOf(ledgerCod, ledgerDod, uncollected)` with `uncollectedValueByDate()` counting barcodes
  **`!isDeducted && !isClosed`** across `scanHistory` and `deletedItems`. Clamp **per currency**.
- `collected = ledger − open` needs fresh views of both sides: `collectedValueIsMeasurable()` covers
  `DB_LISTENER_KEY_HISTORY` · `DB_LISTENER_KEY_DELETED` · `DB_LISTENER_KEY_DAILY_REVENUE`; otherwise show **`—`**.
- ⚠️ Accepted boundary: Delete doesn't deduct ➜ after purge, revenue is slightly inflated. ⛔ Never make Delete deduct
  (that changes business policy).

## ⛔ Automatic cleanup constants — never change without a request

| Rule | Measures | Result | Money |
|---|---|---|---|
| 2 hours (`TWO_HOURS_MS`) | each barcode's `closedAt` | trash `pickup` | untouched |
| over 7×24h (`ABANDON_AGE_MS`) | `item.createdAt`; restored-open barcodes use the later of parent and `barcode.restoredAt`, split by `barcode.isClosed` | trash `expired` | deducted |
| 2 days | `expired` trash items | purge | — |
| 30 days (`TRASH_RETENTION_MS`) | other trash items | purge | — |

- The comparison is `now - createdAt > ABANDON_AGE_MS` (**`>`**) ➜ the label "ផុតកំណត់ ៨ថ្ងៃ" (day 8) is correct ⛔ never
  "fix" it to 7. `trash-modal-test.js` derives `ABANDON_LABEL_DAY = ABANDON_DAYS + 1` from `app.js` and asserts `>`;
  stale-day scans cover "៨ ថ្ងៃ" and "៨ថ្ងៃ".
- `barcode.restoredAt` is optional; never change the parent's or siblings' clocks; one age helper for selection and
  transaction; after partial removal `isClosed` comes from the remaining barcodes.
- Mixed parcels (A closed · B open): 2h rule moves **A only** (`pickup`, money untouched); 7-day rule moves **B only**
  (`expired`, deduct B).
- ⛔ Every close/open goes through `applyBarcodeCloseState(barcode, closed, at)` (never `b.isClosed = x`).
  `barcodeCloseIsRipe()` is the single decider; `normalizeBarcodeCloseStamps()` stamps old data. `executeRestoreItem()`
  resets `closedAt` to `getServerNow()`.

| Marker | Belongs to | Strip before writing to |
|---|---|---|
| `restoreClaimId` · `restoreClaimToken` | `zoew_scan_history_cod_dod` | trash (`stripHistoryOnlyMarkers`) |

- Cleanup, delete, remove and price edits skip items being restored (`itemHasRestoreMarkers()` in the transaction).
- Dead claims are released: `clearStaleRestoreMarkers()` reads the source first; `releaseStaleRestoreClaimForPurge()`
  releases inside a transaction only when not live (lease `RESTORE_CLAIM_LEASE_MS`). A live claim ➜ don't touch. History
  `.write` blocks changing markers whose source has a matching live claim; finalize needs a matching witness and deletes
  the source in the same atomic write (`emu/restore-mutation-emu-test.js`).
- Group purge is atomic ➜ a failed group falls back to one-by-one.

## ⛔ Pickup stats — barcode set as the single basis

```
zoew_daily_pickup_cod_dod/<day>/pickedUpBarcodes/<barcodeKey> = <phoneKey>
packagesPickedUp = number of keys        ← derived mirror
pickedUpPhones   = count per value        ← derived mirror
```

- Customers = distinct phones with ≥ 1 closed barcode; parcels = closed barcodes.
- ⛔ No arithmetic on `packagesPickedUp` or `pickedUpPhones[...]` anywhere: close = write a key · reopen = delete a key ·
  ⛔ never reintroduce delta arithmetic on pickup stats.
- Barcode key = `barcodeRegistryKey(code)`. The server verdict beats the local view (`reapplyPickupMarks()` writes it and
  removes local marks it excludes). A failed write never rolls memory back — toast and let the next snapshot heal.
- A phone change moves ownership of every closed barcode key. Scan merges change nothing.
- Old data: `pickupSetFromRecord(record, seed)` seeds from a recount only when it equals `packagesPickedUp`, else
  placeholder keys `_lg_<phone>_<n>` keep the number (this gate stops Reset from resurrecting).
- Reset writes `{ packagesPickedUp: 0 }` ⛔ never deletes the node (display would recount history). Day basis:
  `getFilterTargetDateKey()`. Money untouched.

## ⛔ Ledger: "apply ➜ revert" is a true inverse

- `ledgerAppliedDelta(before, after)` is the single revert basis — revert the applied delta.
- Verdict `null` = not applied: `ledgerServerVerdict(serverPromise)` (rejection or `committed: false`) ➜
  `{cod:0,dod:0,count:0}`. In-memory revert is idempotent (`ledgerMemoryCompensationClaimed`) in both orders.
- Server-side revert waits for the server verdict: `commitDailyRevenueDelta` / `commitMonthlyRevenueDelta` capture
  `serverBefore`/`serverAfter` inside the transaction.
- Every stats-node write clamps before returning (day · month · pickup). `ZoeErrors.capture('… clamped to 0')` is not a
  clamp. `pickedUpPhones/$phoneKey` requires `> 0` ➜ delete keys reaching 0.
- Keep the reverse: `50 - 12.5` writes exactly `37.5`.

Tools: `ledger-clamp-symmetry-test` · `ledger-failed-apply-revert-test` · `emu/ledger-revert-emu-test` ·
`money-guardian-test` · `price-edit-abort-test` · `revenue-rules-clamp-test` · `revenue-fuzz-test`.

## ⛔ Duplicate barcodes

Layers: debounce 2.5s · `isBarcodeAlreadyUsed()` · **`claimBarcodeInRegistry()` (the only server layer)** ·
`addOrUpdateEntry()` merge. ⛔ Saving needs a real `'claimed'` verdict ("can't verify" ≠ "no duplicate"). Offline RTDB
hangs ➜ `withTimeout` throws ➜ the save is refused.

## ⛔ Orphan keys in `zoew_barcode_registry`

- Release goes through `dbOp()` + `retryAsync()`, then `pendingRegistryReleases`, rerun when `.info/connected` returns
  **and** via `noteDbListenerAlive()` plus `runScheduledCleanup()`. Callbacks apply the snapshot **before**
  `noteDbListenerAlive()`.
- `registryReleaseVerdict(key)`: `release` · `owned` · `defer` (`dbListenerViewIsStale()`); the immediate path has no
  such gate.
- ⛔ Never auto-repair keys that "look orphaned" (a trap is cheaper than duplicate money). Many keys:
  `node audit-tools/registry-orphan-list.js <dump.json>` emits `{"KEY":null,…}` for a human to review and `curl -X PATCH`
  ⛔ never "Import JSON" in Console (it replaces the whole registry). The tool deletes nothing.

## ⛔ Hang ≠ fail — 5 failure modes

| Mode | Happens | Needed |
|---|---|---|
| reject | promise rejects | `.catch()` |
| absent | synchronous `TypeError` | presence check first |
| hang | neither answers nor rejects | a ceiling that settles structurally |
| slow success | resolves after the ceiling | post-commit work runs when it arrives |
| rejected but applied | `disconnect` after a server commit | read the real server first (`runTransactionResolved()`) |

- `withTransactionOutcomeResolution()` wraps `fb` once in `initFirebase()`: every `fb.runTransaction` reads REST with the
  ID token and compares with the sent/pre-send value (`applied` ➜ success · `not-applied` ➜ reject · `unknown` ➜ reject +
  Sentry money). Late cleanups check `cleanupClaimAccountedElsewhere()` first. ⛔ `fb.get()` isn't evidence (cached).
- `dbOp(promise, msg)` (`withTimeout(…, DB_OP_TIMEOUT_MS)`, 15s) for Firebase calls behind locks, incl. via helpers ⛔ no
  direct `await fb.<dataOp>(…)`.
- RTDB queues offline writes ➜ `armLateCommit(promise, onCommitted, onFailed, label)` finishes post-commit work;
  `committed: false` and rejections go to `onFailed`; never claim a rollback while the transaction lives.
  `armLateWrite(promise, onDone)` for key releases; `notifyIfSlow(promise, ms, message)` returns the **same** promise.
- ⛔ No `dbOp()` on trash writes (its catch reverses). ⛔ Exception: `claimBarcodeInRegistry` has no inner ceiling (call
  sites have one).
- Batch work aborts after the first hang (`dbOpStalled(e)`).
- `sw.js` `timedFetch()` is the single network path (`NETWORK_TIMEOUT_MS` 20s, `AbortController` + race); `networkOnly()`
  uses it; the ceiling covers headers only.
- `loadScriptOnce()` has a ceiling and forgets on failure (identity `=== pending`); messages say "too long", not "load
  failed".

# 🔬 Checker discipline

## 13 questions before believing a checker

1. Which files does it scan/run?
2. Which syntax forms (template literals vs concatenation)?
3. Which directions (in **and** out)?
4. Can it fail? ➜ `node audit-tools/checker-coverage.js` (empty `*_APP_DIR`)
5. Can it hang? ➜ `node audit-tools/hang-guard.js`
6. Does failure reach the exit code? ➜ `node audit-tools/exit-code-integrity.js`
7. Does any tool see the seam between 2 files? (a stubbed seam is an untested seam)
8. What state is the system in before asserting? (scenarios must enter the buggy state, not avoid it by timing)
9. Which failure modes do dependencies get (reject · absent · hang · slow success)?
10. Does it see promise rejections (`addInitScript` converters before `.goto()`)?
11. Real failure or measurement artifact? ➜ reverse probe + minimum floor.
12. `PASS` or `SKIP`? ⛔ `SKIP` = couldn't measure ➜ eliminate before claiming green.
13. Does the measurer point at the right tree? `grep -n 'process.env\.[A-Z_]*APP_DIR' audit-tools/<checker>.js` and make
    it fail on purpose once.

## Core tool rules

- Static checkers lock names; behavioral checkers lock outcomes ➜ browser-measurable classes deserve behavioral checkers.
- Absence assertions need minimum floors (count files too).
- Every checker supports `*_APP_DIR` and is called in the `run-all.sh` baseline.
- ⛔ Never exit when a function isn't found — stub it (exiting masks every later assertion).
- ⛔ No single `try` around all scenarios; `await scenario()` for async ones.
- ⛔ Every scenario starts from original stubs; add precondition assertions.
- ⛔ `listen(0, '127.0.0.1')`; `emu/*` namespaces from `emu/ns.js` (`emuNamespace()`).
- ⛔ Label-only `ok()` never called conditionally; count arguments with a real parser.
- ⛔ `checker-coverage.js` skips part 5 under `EXITCODE_CHILD`; hash snapshots skip `.tmp-poison-*`.
- ⛔ Poison shadow files (`.tmp-poison-<pid>-<name>.js`), never originals.
- ⛔ Depth parameters default to at least the depth measured as necessary.
- ⛔ Ceiling assertions use the real ceiling (`cap + N`).
- ⛔ Fuzz floors derive from `RUNS` with a reserved share per state (never a fixed number).
- ⛔ Doc assertions measure facts, not wording; default numbers in docs are read from code; code-text assertions derive the
  function that provides the guarantee instead of hard-coding helper names, and still fail when nothing provides it.
- ⛔ Never write assertions that lock a bug in.
- ⛔ Fuzz asserts after **every** operation, not only at the end.
- Mutation testing asks **who** catches it.
- ⛔ Measure a suspected gap before building a tool for it; delete tools that duplicate existing coverage.
- Sandbox breaks after adding a helper are a good sign (the checker runs real code).

# 📘 Runbook

## Step 0 — setup (once per session)

⛔ Run `run-all.sh` in the session before pushing (don't depend only on GitHub CI). `.github/workflows/audit.yml` runs it
as **4 parallel shards** (`RUNALL_SHARD=k/4`, an emulator per shard, STRICT flags below) ➜ CI green = all 4 green.

```bash
npm ci --prefix ZoeW          # ZoeW React: vite · acorn · playwright-core · firebase (real SDK for emu/tx-disconnect · emu/app-network-e2e)
npm ci --prefix supabase      # Supabase guards: real Postgres (@embedded-postgres) · pg · supabase-js · typescript
npm ci --prefix tools/firebase-provision --ignore-scripts   # real firebase-tools for firebase-provision-test
bash audit-tools/run-all.sh
```

- `run-all.sh` builds the measure tree itself ⛔ never run checkers directly on the repo. One checker:
  `M=$(ZOE_MEASURE_ONLY=1 bash audit-tools/run-all.sh | tail -1)` then `(cd "$M" && node audit-tools/<x>.js)`.
- Full runs take ~10 minutes ➜ run in the background and **commit + push before waiting**.
- Parallel and resumable ([`audit-tools/README.md`](audit-tools/README.md) section 2): `RUNALL_JOBS` lanes · state in
  `<git-dir>/zoe-runall-state.tsv` · `RUNALL_RESUME=1` with the same `*_STRICT` flags reruns only failed/unfinished
  checkers ⛔ never stitch logs · a changed tree ➜ RESUME refuses · `RUNALL_ONLY` / `RUNALL_SHARD` are incomplete runs ·
  one run-all per repo (lock `<git-dir>/zoe-runall-measure.lock`, exit 2; copy the repo to measure in parallel) · new
  emulator/shadow checkers enter `runall_lane()` · `RUNALL_JOBS=1` for serial order.

⛔ **No RTDB emulator ➜ every `emu/*` checker degrades — `SKIP` is not `PASS`.** Count from the real directory
(`audit-tools/emu/*-test.js` plus `crud-rules-flow.js`). Two shapes: `emu/restore-deadlock` · `emu/ledger-revert` ·
`emu/license-seat-rules` · `emu/tx-disconnect` · `emu/app-writes-rules` · `emu/app-network-e2e` ·
`emu/supabase-rules-parity` · `emu/supabase-adapter-parity` print **`SKIPPED`**; `emu/crud-rules-flow` and
`emu/restore-mutation` print **`PARTIAL PASS (… SKIP …)`** — it contains the word `PASS` while the real-rules assertions
never ran. Always read the "partial" and "skipped" numbers of the summary. Before claiming green, run like CI:

```bash
npm i firebase-tools
npx --no-install firebase setup:emulators:database
setsid nohup java -jar ~/.cache/firebase/emulators/firebase-database-emulator-*.jar \
    --port 9000 --host 127.0.0.1 > /tmp/emu.log 2>&1 < /dev/null &
cp firebase-database.rules.json audit-tools/emu/real.rules.json
curl -s "http://127.0.0.1:9000/.json?ns=x"    # must answer null — otherwise the emulator is dead
CRUD_FLOW_STRICT=1 VERSIONSCOPE_STRICT=1 MONEYGUARD_STRICT=1 SUPABASE_STRICT=1 FBPROVISION_STRICT=1 bash audit-tools/run-all.sh
```

- The emulator can die when its shell call ends ➜ run it as a long-lived background task and `curl` again before run-all.
- `money-guardian-test.js` runs only inside run-all (`MONEYGUARD_STRICT=1`).
- ⚠️ **Never `pkill -f <pattern>`** — any pattern appearing in your own command kills your shell. Let processes finish, use
  `timeout`, or `kill <pid>` after checking the PID isn't your shell.

## Step 1 — read real code, try uncovered scenarios

Read real paths (`await` points · session switches · late callbacks) and try behavior. Priorities: new tool classes ·
newly shipped code (`git log`) · real user reports (Sentry, videos).

## Step 2 — rules for every test

Tests extract **real** code into `vm` or run a real browser — never a copy — and must fail on the pre-fix tree:

```bash
BASE_REF=origin/main          # or the commit before your change (branches with many unmerged commits)
git fetch origin main
rm -rf /tmp/baseline && mkdir /tmp/baseline
git archive "$BASE_REF" | tar -x -C /tmp/baseline
bash audit-tools/run-all.sh /tmp/baseline   # what *should* fail will show
```

Archive the **pre-fix** tree, not `HEAD`. Mutations must be real — `grep` that they landed in the real file.

## Step 3 — before commit

```bash
node --check <edited .js files>
node audit-tools/strip-comments.js
CRUD_FLOW_STRICT=1 VERSIONSCOPE_STRICT=1 MONEYGUARD_STRICT=1 SUPABASE_STRICT=1 FBPROVISION_STRICT=1 bash audit-tools/run-all.sh   # emulator alive (step 0)
git diff "$BASE_REF" -- ZoeW/src ZoeW/public ZoeKeyGen | grep '^-'   # unexplained deletions = regressions
```

Bump `CACHE_VERSION` and `APP_VERSION` of apps whose shipped code changed and add a `docs/HISTORY.md` part 1 section.
`version-check` · `version-bump-scope` · `doc-scope-test` run inside `run-all.sh` (directly on the repo they fail falsely).

### ⛔ Impact verification — end of every task (user request)

| # | Question | How |
|---|---|---|
| 1 | What was deleted? | `git diff "$BASE_REF" -- <shipped dirs> \| grep '^-'` — every line explained |
| 2 | How much existing code changed? | `git diff "$BASE_REF" -U3` — separate new code from edits to old code |
| 3 | Who uses what I changed? | `grep` every user of changed shapes/return values/fields |
| 4 | Did behavior change? | run the function **before** (`git show "$BASE_REF":<file>`) and **after** in `vm` on the same cases |
| 5 | Can a new hot-path helper throw? | run it on `undefined` · `null` · `NaN` · object · array |
| 6 | Shared helper? | `error-reporting.js` · `license-verify.js` ship in both apps ➜ bump both |

Green `run-all.sh` is not the answer — step 4 is the strongest proof.

## Harness traps

- `snapshot.val()` returns a deep copy.
- Read store state as `window.<field>` only in the audit build after `waitAuditBridge()`.
- ⛔ In TS sources never declare a local named like a store field (`const fb = firebaseState.fb;` becomes `const fb = fb;`
  in the text view) — `build-audit.mjs` refuses it. The view starts with `\n`.
- The fake SDK supports `fb.increment()` and should enforce real `.validate`.
- Race tests put the other device's write **between** read and write.
- New SW control needs empty `installing`/`waiting` **and** old caches deleted (`OPTIONAL_SHELL` installs after
  `CORE_SHELL`).
- Clear `tr.dataset.sig` before measuring `renderHistory` performance.
- Cleanup fuzz ages stamps per barcode.
- `vm` sandboxes need `setTimeout`: use `(fn, ms) => ms >= 10000 ? setTimeout(fn, ms) : (fn(), 0)`; `Date` must be a real
  constructor.
- A throwing `extractConst()` makes `|| fallback` useless.
- Environment-dependent coverage is accidental ➜ write both paths on purpose.
- `String.replace(from, to)` interprets `$$` ➜ use `replace(from, () => to)`.

## RTDB emulator for rules changes

Start it per **step 0** (never copy those commands elsewhere), then:

```bash
cp firebase-database.rules.json audit-tools/emu/real.rules.json
bash audit-tools/emu/rules.sh
```

- CLI `emulators:start` can't upload rules through the proxy — run the jar.

- Assert a known-bad write is refused before trusting results.

# ⚠️ Expected error patterns — don't "fix"

- `"<X> timed out"` — intentional `withTimeout()`; the Error is built synchronously at the call site.
- `permission_denied` at `repoRerunTransactionQueue` / reconnect — offline transactions replayed after auth/rules changes.
- `"Daily/Monthly revenue underflow clamped to 0"` — safety net (frequent for one day/month ➜ suspect duplicate deduction).
- "⚠️ ទិន្នន័យនេះលែងមានក្នុងប្រព័ន្ធ!" — item gone on the server (frequent ➜ check the device clock).
- False positives: `ResizeObserver` (guarded) · `navigator.credentials` (`biometricPlatformAvailable()` + `try`) ·
  `crypto.subtle` (absent only where the app can't run).
- `waitForZXingThenInitScanEngine()` uses the raw clock on purpose.
- All 7 ZoeW `setInterval` timers run while hidden ⛔ never add a `document.hidden` gate (exception inside a cycle:
  `probeDatabaseLivenessIfIdle()` skips while `hidden`).
- `revenue-fuzz` doesn't cover "7 days + mixed parcel" — `partial-pickup-cleanup-test` does.
- ZTO ⛔ no global circuit breaker (`ZTO_AUTH_EXPIRED` is already `noRetry`).
