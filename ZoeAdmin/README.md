# ZoeAdmin - ប្រព័ន្ធគ្រប់គ្រងអីវ៉ាន់ (Admin)

**ZoeAdmin** គឺជាកម្មវិធីគេហទំព័រ (Web App) សម្រាប់បុគ្គលិកគ្រប់គ្រង (Admin) ប្រើសម្រាប់បញ្ចូល និងគ្រប់គ្រងទិន្នន័យកញ្ចប់ទំនិញ (Parcel/Package) របស់អតិថិជនទាំងអស់ ចាប់ពីការស្កេន Barcode បញ្ចូលកញ្ចប់ថ្មី រហូតដល់ការគណនាប្រាក់ត្រូវទារ (COD/DOD) និងស្ថិតិចំណូល។ កម្មវិធីនេះជា **App គ្រប់គ្រងសំខាន់ (Main Admin)** នៃប្រព័ន្ធ ដែល **ZoeW** (កម្មវិធីទទួល/តាមដានកញ្ចប់) និង **Zoescan** (កម្មវិធីកំណត់ទីតាំង Locker) ទាំងពីរ អានទិន្នន័យរួមគ្នាតាមរយៈ Firebase Database ដូចគ្នា ប៉ុន្តែម្នាក់ៗមានសិទ្ធិខុសគ្នាទៅតាមតួនាទី (Role)។

កម្មវិធីនេះជា **PWA (Progressive Web App)** អាចដំឡើងលើទូរស័ព្ទ ឬកុំព្យូទ័របាន ហើយប្រើ **Firebase** (Authentication + Realtime Database) ជា Backend សម្រាប់ការចូលប្រើប្រាស់ និងផ្ទុកទិន្នន័យ។ Service Worker ទាញយកកូដថ្មីនៅផ្ទៃខាងក្រោយដោយស្វ័យប្រវត្តិនៅពេល Deploy ថ្មី ហើយអនុវត្តនៅពេលបើកកម្មវិធីលើកក្រោយ (មិនរំខានវគ្គដែលកំពុងប្រើប្រាស់ទេ, មិនចាំបាច់ដំឡើង PWA ថ្មីទេ)។

## លក្ខណៈពិសេស (Features)

- 🔐 **ការចូលប្រើប្រាស់សុវត្ថិភាព** — ចូលប្រើប្រាស់តាមរយៈ Firebase Authentication (Email/Password), ត្រូវមានតួនាទី `admin` ជាមុនសិន (គណនី `worker`/`scanner` នឹងត្រូវបដិសេធ ចេញពីប្រព័ន្ធភ្លាមៗ), និងកូដ PIN សុវត្ថិភាពសម្រាប់ការកំណត់រចនាសម្ព័ន្ធ
- 📷 **ស្កេន Barcode** — ស្កេនតាមកាមេរ៉ា (Camera), ម៉ាស៊ីនស្កេន Bluetooth/USB, ឬវាយបញ្ចូលដោយដៃ
- 📦 **បញ្ចូល/គ្រប់គ្រងកញ្ចប់** — កត់ត្រាកញ្ចប់ថ្មីតាមលេខទូរស័ព្ទអតិថិជន, កូដ Barcode ច្រើនក្នុងកញ្ចប់តែមួយ, និងកែប្រែព័ត៌មានអតិថិជន
- 💰 **គណនាប្រាក់ COD/DOD** — គណនាទឹកប្រាក់ត្រូវទារជា USD ($) និង Riel (៛) ដោយស្វ័យប្រវត្តិ តាមអត្រាប្តូរប្រាក់ដែលកំណត់បាន
- ⚙️ **កែប្រែស្ថិតិដោយដៃ** — កែប្រែ COD, DOD និងចំនួនកញ្ចប់ដោយដៃ សម្រាប់ថ្ងៃជាក់លាក់ណាមួយ (ប្រព័ន្ធព្រមានប្រសិនបើខែដែលកែប្រែហួសពីរយៈពេលរក្សាទុក ៣ខែចុងក្រោយ ព្រោះការកែនោះនឹងបាត់វិញ)
- 🏷️ **កែប្រែតម្លៃ Barcode** — កែប្រែ ឬលុប Barcode នីមួយៗក្នុងកញ្ចប់
- 📊 **ស្ថិតិចំណូល** — របាយការណ៍ចំណូលប្រចាំថ្ងៃ និងប្រចាំខែ (COD & DOD ៣ ខែចុងក្រោយ)
- 👥 **ស្ថិតិអតិថិជនយក (Persistent)** — រាប់ចំនួនអតិថិជនតែមួយម្នាក់ៗ (តាមលេខទូរស័ព្ទ) ដែលបានយកកញ្ចប់រួចប្រចាំថ្ងៃ ព្រមទាំងចំនួនកញ្ចប់ (Barcode) ដែលបានប្រគល់ជូនរួច — កត់ត្រាទុកអចិន្ត្រៃយ៍ក្នុង Firebase ដូចស្ថិតិចំណូលដែរ ដូច្នេះលេខមិនថយចុះវិញទេ ទោះកញ្ចប់ដែលបិទរួចហួស ២ម៉ោង ត្រូវផ្លាស់ទីទៅធុងសំរាមស្វ័យប្រវត្តិក៏ដោយ
- 🔍 **ស្វែងរក & Lookup API** — ស្វែងរកកញ្ចប់តាមលេខទូរស័ព្ទ (រកឃើញគ្រប់ថ្ងៃ ទោះកំពុងជ្រើសរើសតម្រងកាលបរិច្ឆេទផ្សេងក៏ដោយ) ព្រមទាំងភ្ជាប់ API ខាងក្រៅ (ឧ. Google Sheet/Apps Script — មើល `google-sheets-api/README.md`) សម្រាប់ស្វែងរកព័ត៌មានអតិថិជនស្វ័យប្រវត្តិពេលស្កេន Barcode, ជាមួយជម្រើសរក្សាទុកភ្លាមៗស្វ័យប្រវត្តិ (មិនចាំចុច "យល់ព្រម") ពេលរកឃើញលេខទូរស័ព្ទត្រូវគ្នា
- 🗑️ **គ្រប់គ្រង "លុប" (លុបជាកញ្ចប់)** — លុបកញ្ចប់ទាំងមូល (លុប = "លុប") ចូល "ទិន្នន័យលុបបណ្តោះអាសន្ន" ដោយ **មិនប៉ះពាល់ស្ថិតិចំណូលឡើយ** (ស្ថិតិប្រចាំថ្ងៃ/ខែនៅដដែលជានិច្ច ទោះស្តារ ឬលុបម្តងទៀតក៏ដោយ) ព្រមទាំងស្តារទិន្នន័យត្រឡប់មកវិញបាន និងលុបជាអចិន្ត្រៃយ៍ (មានប្រអប់បញ្ជាក់ពីរដង)
- ✂️ **ដកកញ្ចប់ (ដកចេញពី Barcode ច្រើន)** — ដកតែ Barcode តែមួយចេញពីកញ្ចប់ (ដក = "ដក") **ដកតម្លៃ/ចំនួនចេញពីស្ថិតិផងដែរ** ហើយស្តារ/ដកម្តងទៀតនឹងបូក/ដកតម្លៃត្រឡប់ទៅវិញដោយស្វ័យប្រវត្តិ (មិនស្ទួន មិនបាត់)
- ⏰ **ច្បាប់លុប/ដកស្វ័យប្រវត្តិ** — កញ្ចប់ដែលបិទបញ្ជីរួច (Closed) លើសពី **២ម៉ោង** ត្រូវលុបស្វ័យប្រវត្តិ (មិនប៉ះស្ថិតិ), កញ្ចប់ដែលនៅសល់មិនទាន់បិទលើសពី **៨ថ្ងៃ** ត្រូវដកចេញស្វ័យប្រវត្តិ (ដកស្ថិតិ), ហើយទិន្នន័យក្នុងធុងសំរាមលើសពី **១០ថ្ងៃ** ត្រូវលុបចោលជាអចិន្ត្រៃយ៍ស្វ័យប្រវត្តិ
- 📤 **Export ទិន្នន័យ** — Export របាយការណ៍ដែលកំពុងបង្ហាញជា Excel (.xlsx), PDF (មានអក្សរខ្មែរច្បាស់ តាមរយៈ browser print-to-PDF, បូកសរុប COD/DOD/ចំនួន, និងលេខទំព័រ/ពេលវេលា Export), ឬ CSV សម្រាប់ Google Sheet
- 📋 **តារាងទិន្នន័យអតិថិជន (Customer Data Table)** — ទិដ្ឋភាព Read-only នៃទិន្នន័យអតិថិជនពី Google Sheet ដែលភ្ជាប់ (មើល `google-sheets-api/README.md`)
- 🔄 **Sync ទិន្នន័យសម្រាប់ Zoescan** — ប៊ូតុង "កំណត់ទិន្នន័យ Scanner Lookup ឡើងវិញ" (ក្នុងម៉ឺនុយ "⋯") សម្រាប់ Sync ទិន្នន័យចាស់ចូល `zoew_scanner_lookup` ប្រសិនបើ Zoescan មិនឃើញកញ្ចប់ណាមួយ
- 📱 **ដំឡើងជា App បាន (PWA)** — គាំទ្រ Service Worker សម្រាប់ប្រើប្រាស់ក្រៅបណ្តាញ (Offline) និងទទួលបានកូដថ្មីស្វ័យប្រវត្តិគ្រប់ពេល Deploy ដោយមិនចាំបាច់ដំឡើងសាថ្មីទេ

## គោលការណ៍ "លុប" vs "ដក" (Delete vs Remove Policy)

| | លុប (Delete) | ដក (Remove) |
|---|---|---|
| អ្វីខ្លះ | លុបកញ្ចប់ទាំងមូល | ដក Barcode តែមួយចេញពីកញ្ចប់ច្រើន Barcode |
| ប៉ះស្ថិតិចំណូល? | **ទេ** — ស្ថិតិប្រចាំថ្ងៃ/ខែនៅដដែលជាអចិន្ត្រៃយ៍ | **បាទ/ចាស** — ដកតម្លៃ/ចំនួនចេញពីស្ថិតិភ្លាមៗ |
| ស្តារមកវិញ (Restore)? | មិនបូកអ្វីបន្ថែម (ព្រោះមិនធ្លាប់ដកចេញ) | បូកតម្លៃត្រឡប់ចូលស្ថិតិវិញ |
| លុប/ដកម្តងទៀត? | មិនដកអ្វីបន្ថែម (Idempotent) | ដកតម្លៃម្តងទៀត |
| ស្ថានភាព (បានហៅ/បិទបញ្ជី) | រក្សាទុកគ្រប់ពេល ទោះកន្លងកាត់ Delete→Restore→Delete ច្រើនដងក៏ដោយ | រក្សាទុកគ្រប់ពេលដូចគ្នា |

នេះជាគោលការណ៍អាជីវកម្ម មិនមែន Bug ទេ ហើយត្រូវបានផ្ទៀងផ្ទាត់ត្រឹមត្រូវហើយ (សម្រាប់ព័ត៌មានលម្អិត សូមមើល PDF Guide របស់ប្រព័ន្ធ)។

## សុវត្ថិភាព (Security)

- ការចូលប្រើប្រាស់តម្រូវឲ្យមានគណនី Firebase Authentication **ត្រូវជាមួយតួនាទី `admin`** (កំណត់ត្រង់ Server-side តាម `user_roles/$uid` — មិនអាចក្លែងបានទេ)
- **ព្រំដែនសុវត្ថិភាពពិតប្រាកដស្ថិតនៅ Server-side** តាមរយៈ `firebase-database.rules.json` (មិនមែន Client-side ទេ) — Rule កំណត់ច្បាស់ថា `admin`/`worker`/`scanner` នីមួយៗអានសរសេរអ្វីបានខ្លះ
- Scanner (Zoescan) លែងអានឃើញ COD/DOD ឬស្ថានភាពអាជីវកម្មនៃកញ្ចប់ណាមួយបានទៀតហើយ — មានតែ `zoew_scanner_lookup` (លេខទូរស័ព្ទ + Barcode + Locker តែប៉ុណ្ណោះ) ដែល Scanner អាចអានបាន
- មានកូដ PIN ដាច់ដោយឡែកសម្រាប់ការកែប្រែការកំណត់រចនាសម្ព័ន្ធ (Config)
- ទិន្នន័យទាំងអស់ដែលមកពី Firebase (លេខទូរស័ព្ទ, Barcode, ព័ត៌មានអតិថិជន) ត្រូវបាន Escape មុននឹងបង្ហាញ ដើម្បីការពារការវាយប្រហារ XSS
