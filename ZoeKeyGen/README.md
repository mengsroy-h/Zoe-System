## មុខងារ

### Activation Key

| មុខងារ | ខ្លឹមសារ |
|---|---|
| **បង្កើត Key** | Sign ដោយ **ECDSA P-256** ជាមួយសុពលភាពតាមចំនួនថ្ងៃ · **ចំនួនឧបករណ៍ (១–៥)** និង note សម្គាល់អតិថិជន |
| **Revoke** | ដកហូតសិទ្ធិភ្លាមៗពីខាង server — ឧបករណ៍ដែលកំពុងប្រើបាត់សិទ្ធិនៅការពិនិត្យបន្ទាប់ (យ៉ាងយូរ ១៥ នាទី) |
| **Extend** | បន្ថែមសុពលភាពដោយផ្លាស់ **ពិដានខាង server** (`expiresAt`) |
| **📱 ចំនួនឧបករណ៍** | កំណត់ថា Key ១ Activate បានលើឧបករណ៍ប៉ុន្មាន (១–៥) — សម្រាប់អតិថិជនដែលមានទូរស័ព្ទច្រើន |
| **ដោះឧបករណ៍** | ដោះឧបករណ៍ដែលចងរួច **ទាំងអស់** ចេញពី Key ដើម្បីឲ្យអតិថិជនប្តូរទូរស័ព្ទបាន |
| **តារាង Key** | ស្ថានភាព · ស្លាកឧបករណ៍ (📱 ចងរួច/ពិដាន) · ថ្ងៃចេញ · ថ្ងៃផុតកំណត់ · note |

✅ **Key ដែល Extend រួច activate លើឧបករណ៍ថ្មីបាន** — តាំងពី ZoeW `2.20.6`
ការ activate យកពិដានពី **`expiresAt` លើ server** ជំនួស `exp` ដែល sign រួច។
⛔ ហត្ថលេខានៅតែជាការផ្ទៀងផ្ទាត់ភាពពិត ៖ Key ដែល Revoke · មិនមានក្នុង DB ·
ឬហត្ថលេខាខុស **នៅតែបដិសេធដដែល**។

### Setup Link និង QR

បង្កើត `https://<app-site>/?setup=<config>` ព្រមទាំង QR ដើម្បីឲ្យអតិថិជន
មិនបាច់វាយ Firebase Config ដោយដៃ។ Base URL ចងចាំទុករវាងវគ្គ។

វាល **Sentry DSN** (ស្រេចចិត្ត · ចងចាំទុកដែរ) ដាក់ការរាយការណ៍កំហុសចូល Link
ផងដែរ ➜ ឧបករណ៍អតិថិជនផ្ញើកំហុសមកអ្នកដោយស្វ័យប្រវត្តិ ដោយមិនបាច់វាយ DSN
លើគ្រប់គ្រឿង។ ទទួលតែ `https://` ដែល host ជា `sentry.io` ឬ `*.sentry.io`;
ទុកឲ្យទទេ ➜ ឥរិយាបថដូចមុន។

⛔ នៅខាង ZoeW ការបើក Setup Link **មិនរក្សាទុកដោយស្វ័យប្រវត្តិទេ** — វាឆ្លង
PIN gate ដដែលនឹងការកែ Config ដោយដៃ ហើយ query string លុបចេញភ្លាម។

## របៀបប្រើប្រាស់

### ១. Deploy

Netlify site មួយ ដោយ **Base directory = `ZoeKeyGen`** · Build command **ទទេ** ·
Publish directory **`.`**។

Firebase rules របស់ **License Project** (`ZoeKeyGen/firebase-database.rules.json`)
ត្រូវ paste ចូល Firebase Console ➜ **Publish** ដោយដៃ។ ⛔ វាជា Project
**ដាច់ដោយឡែក** ពី Project អាជីវកម្ម — កុំយកទៅច្រឡំគ្នា។

### ២. ដំឡើងលើកដំបូង

1. បង្កើតគណនី Firebase Auth ក្នុង **License Project**។
2. ដាក់ `user_roles/<uid>` = `admin` ក្នុង Database នោះ — ⛔ អ្នកប្រើដែល
   មិនមែន admin ត្រូវចាកចេញភ្លាមក្រោយចូល។
3. បើក App ➜ បញ្ចូល **Firebase Config** របស់ License Project (ការពារដោយ PIN)។
4. **ចូលប្រព័ន្ធ** ➜ កំណត់ **Security PIN**។
5. **Signing Key** ៖ បង្កើតគូកូនសោថ្មី **ឬ** ផ្ទុកកូនសោឯកជនដែលមានស្រាប់។
   ⛔ សោសាធារណៈត្រូវតែស្មើនឹងអ្វីដែល embed ក្នុង `license-verify.js` របស់ ZoeW។

### ៣. ចេញ Key ថ្មីឲ្យអតិថិជន

1. ផ្ទុក **Signing Key** (ឯកជន) ចូលវគ្គ។
2. កាត «បង្កើត Key ថ្មី» ➜ បញ្ចូល **ចំនួនថ្ងៃសុពលភាព** និង **note**
   (ឈ្មោះអតិថិជន ឬលេខទូរស័ព្ទ)។
3. ចុចបង្កើត ➜ ចម្លង Key ➜ ផ្ញើទៅអតិថិជន។
4. អតិថិជន paste Key ចូល ZoeW ➜ ត្រូវការអ៊ីនធឺណិត។

### ៤. Provision ឧបករណ៍ថ្មីលឿន (Setup Link / QR)

1. កាត «បង្កើត Setup Link» ➜ បញ្ចូល **Base URL** របស់ site ZoeW។
2. Paste **Firebase Config** របស់ Project អាជីវកម្ម។
3. (ស្រេចចិត្ត) បំពេញ **Sentry DSN** ➜ កំហុសលើឧបករណ៍អតិថិជនមកដល់អ្នក។
4. ចុចបង្កើត ➜ ចែក **Link** ឬឲ្យអតិថិជនស្កេន **QR**។
5. ខាង ZoeW ៖ Config បំពេញស្វ័យប្រវត្តិ ➜ អ្នកប្រើវាយ PIN ➜ រក្សាទុក។

### ៥. Revoke · Extend · ដោះឧបករណ៍

- **Revoke** ៖ បញ្ជី Key ➜ ចុច Revoke ➜ ឧបករណ៍នោះឈប់ដំណើរការក្នុងរយៈពេល
  យ៉ាងយូរ ១៥ នាទី (ឬពេលបិទបើក App)។
- **Extend** ៖ បញ្ជី Key ➜ ចុច Extend ➜ បញ្ចូលចំនួនថ្ងៃបន្ថែម។ ⛔ ត្រូវការ
  អ៊ីនធឺណិត និងម៉ោង server ដែលផ្ទៀងផ្ទាត់បាន — បើអត់ វាបដិសេធដោយសារជាក់លាក់
  ជំនួសការចេញ Key ដែល sign ដោយម៉ោងខុស។
- **📱 ចំនួនឧបករណ៍** ៖ អតិថិជនមានទូរស័ព្ទច្រើន ➜ បញ្ជី Key ➜ ចុចប៊ូតុងនេះ
  ➜ វាយលេខ **១ ដល់ ៥**។ ឧបករណ៍ថ្មីនឹង Activate បានរហូតដល់ចំនួននោះ។
  អ្នកអាចកំណត់វាតាំងពីពេលបង្កើត Key ដែរ (ប្រអប់ «ចំនួនឧបករណ៍»)។
  ⛔ ការ **បន្ថយ** លេខធ្វើឲ្យឧបករណ៍ដែលលើសលែងប្រើ Key នោះបាន។
- **🔓 ដោះឧបករណ៍** ៖ អតិថិជនប្តូរទូរស័ព្ទ ឬលុប site data ➜ ចុចប៊ូតុងនេះ ➜
  ឧបករណ៍ដែលចងរួច **ទាំងអស់** ត្រូវដោះ ហើយឧបករណ៍ថ្មីរហូតដល់ពិដាន Activate
  បាន។ ស្លាកក្នុងតារាងប្រាប់ស្ថានភាព ៣ ៖ **📱 <ចំនួន>/<ពិដាន>** ·
  **📱 ទំនេរ** · **⚠️ ពិនិត្យមិនបាន** (rules មិនទាន់ Publish)។

## ប្រព័ន្ធសុវត្ថិភាព

App នេះកាន់ **កូនសោ signing** ដូច្នេះវាតឹងរឹងជាង ZoeW។

### ការចូលប្រើ

| ស្រទាប់ | អ្វី |
|---|---|
| **Firebase Authentication** | អ៊ីមែល + ពាក្យសម្ងាត់ លើ **License Project ដាច់ដោយឡែក** |
| **តួនាទី `admin`** | ក្រោយចូល App អានតួនាទីពី `user_roles`; មិនមែន admin ➜ ចាកចេញភ្លាម |
| **ការពិនិត្យតួនាទីមានពេលកំណត់ពិត** | ពេល socket យឺត វាធ្លាក់ទៅផ្លូវ REST ដែលមាន `AbortController` ➜ មិនព្យួររហូត ហើយព្យាយាមឡើងវិញស្វ័យប្រវត្តិពេលបណ្តាញត្រឡប់មក |
| **Security PIN** | ការពារ Config; PBKDF2-SHA256 ១៥០,០០០ ជុំ |

### កូនសោ signing

- កូនសោឯកជន **មិនរក្សាទុកជាអចិន្ត្រៃយ៍ក្នុង App ទេ** — ផ្ទុកចូលក្នុងវគ្គ
  ដើម្បី sign រួចលុបចេញ។
- ការចាកចេញ ឬការចាក់សោ **លុបកូនសោចេញពីសតិ និងចេញពី DOM**។
- សោសាធារណៈ embed ក្នុង `license-verify.js` របស់ ZoeW ➜ Key ក្លែងក្លាយ

### ទិន្នន័យ និង Rules

- **`license_keys/$appCode/$keyId` អានបានជាសាធារណៈ** តែ `expiresAt` និង
  `revoked` ប៉ុណ្ណោះ ព្រោះការពិនិត្យខាង ZoeW ជា REST គ្មាន auth។
- **Metadata រសើប** (`note`, `createdBy`, `issuedAt`, `scope`) ស្ថិតក្នុង
  `license_keys_meta` ដែល **អាន/សរសេរបានតែ admin**។
- **`license_seats/$appCode/$keyId/<slot>` ចង Key ទៅឧបករណ៍** ៖ អតិថិជន
  សរសេរវាបានតែពេល slot នោះទំនេរ ឬពេលជា **ឧបករណ៍ដដែល**។ ចំនួន slot ដែល
  ប្រើបានមកពី **`maxDevices` របស់ Key** ដែលមានតែ admin សរសេរបាន ➜ ⛔ ការកែ
  លេខខាង client មិនផ្តល់កៅអីបន្ថែមទេ។ គ្មាន `maxDevices` = **១**។
  ការលុប (ដោះឧបករណ៍) ជារបស់ **admin តែម្នាក់**; ការរាយបញ្ជីកៅអីត្រូវបដិសេធ
  ដូច្នេះគេរាប់អតិថិជនមិនបាន។
