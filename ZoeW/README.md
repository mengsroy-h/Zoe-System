## មុខងារ

### ការស្កេន និងការបញ្ចូល

- **ផ្លូវស្កេន ៣** — កាមេរ៉ា · ម៉ាស៊ីនស្កេន hardware · រូបភាពក្នុងឧបករណ៍។
  គ្រប់ផ្លូវឆ្លងកាត់ចំណុចបំបែកតែមួយ ដូច្នេះឥរិយាបថដូចគ្នាបេះបិទ។
- **Engine ZXing C++ ចងក្រងជា WebAssembly** ស្ថិតក្នុង repo។ លើ Android វាប្រើ
  `BarcodeDetector` ដើមរបស់ប្រព័ន្ធពេលមាន។
- **ទទួលតែ CODE-128** — format ដែលមានលេខផ្ទៀងផ្ទាត់ជាកាតព្វកិច្ច។
- **ការបញ្ជាក់ ២ ស៊ុមជាប់គ្នា** លើផ្លូវកាមេរ៉ា ជាជាន់ការពារទី ២។
- **ជួរអានសម្របតាមឧបករណ៍** និង **ការទប់ស្កាត់ Barcode ស្ទួន ៥ ជាន់**។
- **របៀបស្កេន ៣** — បញ្ចូលកញ្ចប់ · កំណត់ទីតាំង Locker · ស្កេនដកកញ្ចប់។
  របៀបដកបង្ហាញ Barcode, លេខទូរស័ព្ទ, Locker, COD/DOD និងស្ថានភាពឲ្យ
  ផ្ទៀងផ្ទាត់ជាមុន ហើយមិនត្រូវបានចងចាំក្រោយ Refresh ដើម្បីកុំដកដោយចៃដន្យ។

- **ទាញបញ្ជីកញ្ចប់ពី ZTO** (ស្រេចចិត្ត · លំនាំដើម **បិទ**) — ទាញបញ្ជីកញ្ចប់ដែល
  ZTO ស្កេន «អីវ៉ាន់មកដល់» តាមជួរកាលបរិច្ឆេទ ➜ បែងចែកជា ៤ ក្រុម (ថ្មី · មានរួច ·
  ស្ទួន · រំលង) ➜ បញ្ចូល **តែក្រុមថ្មី** តាមទ្វារដដែលនឹងការស្កេនដោយដៃ។

### ទិន្នន័យ និងចំណូល

- **COD និង DOD** ក្នុងកញ្ចប់តែមួយ បូកលេខទូរស័ព្ទ និងទីតាំង Locker។
- **Barcode ច្រើនក្នុងកញ្ចប់តែមួយ** — កែតម្លៃម្តងមួយបាន; ការដកត្រូវស្កេន
  Barcode ពិត និងបញ្ជាក់ក្នុងផ្ទាំងសុវត្ថិភាព។
- **ស្ថិតិប្រចាំថ្ងៃ និងប្រចាំខែ** ៖ **អតិថិជនយក** = លេខទូរស័ព្ទផ្សេងៗគ្នាដែល
  មាន barcode បិទ >= ១ · **កញ្ចប់យក** = ចំនួន barcode បិទ។
- **«ចំណូល» = តម្លៃកញ្ចប់ដែលអតិថិជន *យករួច* ប៉ុណ្ណោះ។** កញ្ចប់ដែលនៅរង់ចាំ
  បង្ហាញដាច់ដោយឡែកជា **«មិនទាន់យក»** ហើយលេខទាំង ២ បូកគ្នាស្មើ **«តម្លៃកញ្ចប់
  ទាំងអស់»**។ ហេតុផល ៖ កញ្ចប់ដែលមិនយកក្នុង ៧ ថ្ងៃ ត្រូវដកចេញស្វ័យប្រវត្តិ
  (ត្រឡប់ទៅសាខាកណ្តាល) ➜ ការរាប់វាជាចំណូល ធ្វើឲ្យលេខប៉ោងបណ្តោះអាសន្ន។
  បើប្រវត្តិមិនទាន់មកដល់គ្រប់ ជួរចំណូលបង្ហាញ **`—`** («វាស់មិនបាន» ≠ «សូន្យ»)។
  **ចំណូលរបស់ខែ = ផលបូកចំណូលរបស់ថ្ងៃនីមួយៗ** ➜ ស្ថិតិប្រចាំថ្ងៃ និងរបាយការណ៍ខែ
  បង្ហាញលេខដូចគ្នាជានិច្ច។
- **💵 ចំណូលប្រចាំថ្ងៃ (តាមថ្ងៃយក)** ៖ ទឹកប្រាក់កញ្ចប់ដែលបិទ «យក» **ក្នុងថ្ងៃ
  នោះ** — មិនថាកញ្ចប់នោះស្កេនចូលថ្ងៃណា។ រក្សា **៧ ថ្ងៃចុងក្រោយ** ក្នុង Database
  ហើយថ្ងៃចាស់ជាងនោះលុបចោលស្វ័យប្រវត្តិ។ ⛔ វា **គិតតាមអ័ក្សផ្សេង** ពី «📅 កញ្ចប់
  ប្រចាំថ្ងៃ» (ដែលគិតតាម *ថ្ងៃស្កេនចូល*) ➜ លេខ ២ នេះ **មិនត្រូវរំពឹងថាស្មើគ្នា**។
  វា **មិនប៉ះលុយក្នុងប្រព័ន្ធ** — វាជាកញ្ចក់នៃការចុច ✅ បិទ ប៉ុណ្ណោះ។
- **អត្រាប្តូរប្រាក់រៀល** ចែករំលែករវាងឧបករណ៍ទាំងអស់។
- **តម្រងតាមថ្ងៃ** និងស្វែងរកតាមកន្ទុយលេខទូរស័ព្ទ ៣–៤ ខ្ទង់។
- **ធុងសំរាម និងការស្តារ**។
- **ថ្ងៃ និងម៉ោងគិតតាម `Asia/Phnom_Penh` គ្រប់ឧបករណ៍** — ឧបករណ៍ដែលកំណត់
  តំបន់ម៉ោងផ្សេង ក៏ចុះចំណូលចូលថ្ងៃដដែល។

### ១. Deploy

### ២. ដំឡើងឧបករណ៍ថ្មី

1. បើក URL ➜ paste **Activation Key** (ត្រូវការអ៊ីនធឺណិត)។
2. បញ្ចូល **Firebase Config** ៖ ⚙️ របា Slide ➜ Config — ឬបើក **Setup Link/QR**
   ដែលចេញពី ZoeKeyGen (នៅតែសុំ PIN មុនរក្សាទុក)។

4. កំណត់ **Security PIN** ➜ ⚙️ របា Slide។
5. (ស្រេចចិត្ត) បើក **ក្រយៅដៃ/មុខ** និងដំឡើងជា PWA។

### Firebase Rules

- Root **default-deny**; គ្រប់ node តម្រូវ `auth != null`។
- **Schema validation** — ប្រភេទវាល ជួរតម្លៃ និង `$other: false`។
- **Claim/witness fence** លើការស្តារ និងការលុបទាំងអស់ ➜ replay និងការគិតលុយ
  ស្ទួនកើតមិនបាន។
- ⛔ Rules **មិន deploy ស្វ័យប្រវត្តិទេ** — paste ចូល Console ➜ Publish។

### ការជូនដំណឹងពីកំហុស (Sentry alert)

កំហុសនីមួយៗត្រូវបានដាក់ស្លាក **`zone`** តាមកម្រិតគ្រោះថ្នាក់។ ⛔ **Sentry
alert rule ស្វែងរកបានតែលើ tag** — មិនមែនលើ `extra` ទេ — ដូច្នេះស្លាកនេះជា
អ្វីដែលធ្វើឲ្យការជូនដំណឹង «តែពេលមានរឿងធ្ងន់» សរសេរកើត។

| `zone` | មានន័យថា | ឧទាហរណ៍ |
|---|---|---|
