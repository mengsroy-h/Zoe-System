## ជំហាន ២ — បច្ចេកទេសដែលរកឃើញកំហុសពិត (មិនមែនការអានកូដ)

### ក. តារាងប្រៀបធៀបផ្នែកបងប្អូន
ដាក់ផ្នែក ២ ដែលមាន **រូបរាងដដែល** ក្បែរគ្នា រួចសួរជួរនីមួយៗ។

### ខ. `grep` កន្លែងហៅ **ទាំងអស់** របស់ធនធានចែករំលែក
ពិនិត្យ **ម្តងមួយ** ៖ សរសេរតាម delta របស់ **សតិ** ឬតាម **សាលក្រម server**?

### គ. ដាក់ dependency ក្នុងរបៀបបរាជ័យទាំង ៤
បដិសេធ · **អវត្តមាន** (`TypeError` synchronous) · **ព្យួរ** · **យឺតតែជោគជ័យ** —
មើលតារាងក្នុង `CLAUDE.md` ផ្នែក «ការព្យួរ ≠ ការធ្លាក់»។
🔴 អនុវត្តលើ **ជំហានទី ២ (ការដកវិញ)** ដែរ — ថ្នាក់នោះមានអ្នកយាមរួចហើយ ៖
`ledger-failed-apply-revert-test` · `emu/ledger-revert-emu-test`។
⛔ **RTDB មិនបដិសេធពេលក្រៅបណ្តាញទេ — វា *ចាក់ជួរ*។** អ្នកកេះពិតជា
`permission_denied` និង `maxretry`។

### ឃ. 🔴 **កម្រិតបូក (aggregation level)** — បច្ចេកទេសដែលរកឃើញ 2.31.6
រូបមន្តតែមួយអាចត្រូវហៅនៅ **កម្រិតផ្សេងគ្នា** រួចឲ្យលេខផ្សេងគ្នា ៖

```
ថ្ងៃ ៖ Σ_d f(x_d)      ធៀបនឹង      ខែ ៖ f(Σ x_d)
```

ពួកវាស្មើគ្នា **តែពេល `f` ជាលីនេអ៊ែរ**។ រាល់ `Math.max(0, …)` · `clamp` ·
`Math.round` · `Math.min` ធ្វើឲ្យវា **មិនលីនេអ៊ែរ** ➜ ២ អេក្រង់បង្ហាញ ២ លេខ។

**របៀបស្កេន** ៖ រកគ្រប់កន្លែងដែលបូកលើសំណុំ (`forEach` + `+=` · `reduce`)
រួចសួរ ៖ «តើ clamp ឋិតនៅ **ខាងក្នុង** ឬ **ខាងក្រៅ** ការបូក?»។
⛔ **checker ស្តាទិចដែលចាក់សោ *ការហៅ* មើលមិនឃើញថ្នាក់នេះទេ** — ត្រូវការ
checker ដែល **អានលេខចេញពី HTML** (`stats-screen-agreement-test`)។

## ជំហាន ៣ — វិន័យរបស់ឧបករណ៍ (⛔ ឧបករណ៍មុន ➜ ទើបកែកូដ)

**រកឃើញកំហុស ➜ សាង checker ជាមុន ➜ បញ្ជាក់ថាវាធ្លាក់លើ `origin/main` ➜ ទើបកែកូដ។**

```bash
rm -rf /tmp/baseline && mkdir /tmp/baseline
git fetch origin main && git archive origin/main | tar -x -C /tmp/baseline
<CHECKER>_APP_DIR=/tmp/baseline node audit-tools/<checker>.js   # ត្រូវធ្លាក់!
mkdir -p /tmp/emptytree && <CHECKER>_APP_DIR=/tmp/emptytree node audit-tools/<checker>.js  # ត្រូវធ្លាក់ដែរ!
```

- បើតេស្តថ្មី**ជោគជ័យ**លើ tree មុនកែ ➜ វាមិនចាប់អ្វីទេ ➜ សរសេរឡើងវិញ
- ⛔ checker ថ្មីត្រូវ ៖ មាន `*_APP_DIR` · ចុះឈ្មោះក្នុង `run-all.sh`
  **ទាំង ២ កន្លែង** (ការរត់ធម្មតា **និង** ផ្នែក baseline) · ធ្លាក់លើថតទទេ ·
  មាន **ជាន់អប្បបរមា** និង **probe ទិសផ្ទុយ** · exit code ១ ពិត
- ⛔ រកឈ្មោះ function មិនឃើញ ➜ **stub** មិនមែន `process.exit` (បើអត់
  ការអះអាងខាងក្រោមត្រូវបិទបាំង)
- ⛔ កុំសាង checker ស្ទួន — សាកឧបករណ៍ចាស់ជាមុនសិន
- ⚠️ helper ថ្មីធ្វើឲ្យ sandbox បាក់ (`ReferenceError`) ជា **សញ្ញាល្អ**
- ⛔ ក្រោយសាង checker ថ្មី ត្រូវរត់ `checker-coverage.js` ជាមុន — វាចាក់សោ
  ថា checker ថ្មីនោះពិតជាមើលកូដ

🔴 **ពេល mutation មួយ *រស់រាន*** ៖ សួរ «តើវា equivalent ដោយសារ **សាខានោះជា
កូដងាប់** ឬ?» ➜ បើមែន ⛔ **លុបសាខានោះចេញ** មិនមែនសរសេរ assertion ក្លែងទេ។

⛔ **តម្លៃសាកល្បងដែលជា *លេខមូល* លាក់ mutation នៃការបង្គត់។** វាស់បាន
(2.31.6) ៖ mutation «បង្គត់ត្រឹមដុល្លារ» **រស់រាន** ព្រោះសេណារីយ៉ូទាំងអស់
បូកជាលេខគត់ ($20 · $30 · $80) ➜ ត្រូវមានសេណារីយ៉ូ **ដែលចម្លើយមានសេន**។

⛔ **allowlist មិនវាស់ថាកូដនោះ *រស់* ឬអត់ទេ។** វាស់បាន (2.31.6) ៖ ធាតុ
`ACCEPTED` ក្នុង `code-duplication-test` ទទួលយកការជាន់គ្នា **១៥ បន្ទាត់**
ដោយហេតុផលសមរម្យ — តែ **៧ បន្ទាត់ក្នុងនោះជាកូដងាប់** (function ដែលគ្មាន
កន្លែងហៅ)។ ⛔ មុនបន្ថែមធាតុ allowlist ថ្មី ត្រូវ `grep` រកកន្លែងហៅជាមុនសិន។

   ប៉ុន្មានលើ `main` ➜ ប៉ុន្មានក្រោយកែ · mutation ប៉ុន្មាន ➜ ចាប់បានប៉ុន្មាន

២. 🔴 **ចំណាត់ថ្នាក់នៃកំហុសនីមួយៗ** ៖ **កំហុសសកម្ម** ធៀបនឹង **អន្ទាក់រង់ចាំ**។
   ⛔ **ប្រាប់មុនថា ពេលសាកលើទូរស័ព្ទ តើគួរឃើញអ្វី** — បើចម្លើយគឺ «អ្នកនឹង
   មិនឃើញអ្វីទេ» ត្រូវនិយាយវា **មុន**។

៣. **ពាក្យបញ្ជាឲ្យ *ខ្ញុំ* បញ្ជាក់កំហុសដោយខ្លួនឯងលើ `main`** — copy-paste បាន
   ភ្លាម ព្រមទាំងលទ្ធផលពិតដែលត្រូវឃើញ (`❌ ធ្លាក់ N` ធៀប `✅ ok N`)។

៤. **តារាង «វាស់តែមិនរកឃើញអ្វី»**

៥. ⛔ **អ្វីដែលអ្នក *មិនអាច* អះអាងបាន** និងតំបន់ 📝

៦. **បញ្ជីតេស្តលើឧបករណ៍ពិត ជាតារាង** ៖ លេខពិត **ក្នុងមួយជួរនៃកាតស្ថិតិ**
   (`កញ្ចប់សរុប` · `ចំណូល (យករួច)` · `តម្លៃកញ្ចប់ទាំងអស់` · `មិនទាន់យក` ·
   ស្ថិតិយក — ⛔ ពួកវាមានន័យខុសគ្នា) · និង **លេខដែលនឹងឃើញបើមិនកែ**។
   ⛔ តេស្តដែលត្រូវការឧបករណ៍ ២ ឬការបិទបណ្តាញ ត្រូវសរសេរឲ្យច្បាស់ថាហេតុអ្វី
   **ការចុចលើឧបករណ៍តែមួយបង្កើតកំហុសឡើងវិញមិនបាន**

៧. **PR ជាភាសាខ្មែរ** ជាមួយភស្តុតាងលេខ ⛔ **ព្រមទាំងលទ្ធផល CI ដែលរត់ក្នុង
   session** (GitHub Actions លែងរត់ — អស់កូតា)

៨. 🔄 **Update ឯកសារនេះ (`docs/AUDIT-PROMPT.md`) ក្នុង commit ដដែល** ៖
   បន្ថែមមេរៀនដែល **វាស់បាន** · ⛔ **រួញ** មេរៀនណាដែលទទួលឧបករណ៍ចាក់សោជុំនេះ
   ទៅជាការយោងឈ្មោះឧបករណ៍ · លុបអ្វីដែលការវាស់បដិសេធ · បង្ហាញតារាង
   «អ្វីដែលប្រែធៀបនឹងជុំមុន» ➜ **មិនវែងជាងជុំមុន** លុះត្រាតែមានហេតុផល។

## ⛔ ព្រំដែន

- **កុំ merge ចូល `main` ដោយគ្មានការស្នើពីខ្ញុំ** (ប្រព័ន្ធនេះមានលុយពិត)
- ⛔ **CI ត្រូវរត់ក្នុង session** ហើយរាយលេខ — GitHub Actions អស់កូតា ➜
  **ការរង់ចាំ CI បៃតងលើ GitHub ជាការរង់ចាំដែលមិនចប់**
- កុំប៉ះ **PTR · ចលនាផ្ទាំងប្រវត្តិ · ការរមូរ** ដោយគ្មានការស្នើ
- កុំកែតាមការសង្ស័យ — **ការវាស់ទើបជាភស្តុតាង មិនមែនការអានកូដទេ**
- ⛔ **បើការវាស់បដិសេធសម្មតិកម្មរបស់អ្នក ត្រូវនិយាយវាឲ្យច្បាស់** រួចបន្តទៅមុខ
- រាល់ការសរសេរជាភាសាខ្មែរ (កូដនៅជាអង់គ្លេស)
