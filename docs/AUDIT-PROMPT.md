## ជំហាន ១ — ⛔ ផ្នត់គំនិត

**`run-all.sh` បៃតង ≠ គ្មានកំហុស។** កំណែ 2.26.x · 2.30.3 · 2.31.6 · **2.31.7**
សុទ្ធតែធ្លាក់លើ tree បៃតង ១៣០–១៥៨ · SKIP 0។

សួរសំណួរទាំង ៥ នេះ **រាល់ជុំ** ៖

1. ⛔ **«តើអ្វី *មិនទាន់* មានអ្នកវាស់?»** មិនមែន «តើ checker ណាក្រហម?»
2. ⛔ **«តើអថេរដែលខ្ញុំពឹងលើ អាចនៅតែពិត *ទាំងសងខាង* នៃកំហុសបានទេ?»**
   🔴 2.31.6 ៖ «អេក្រង់ខែហៅ `collectedValueOf()`» — ពិតទាំង ២ ខាង (កំហុសនៅ
   *កម្រិត*)។ 🔴 2.31.7 ៖ `collectedValueIsMeasurable()` *ពិត* ពិនិត្យថា
   ទិដ្ឋភាពគ្រប់ — គ្រាន់តែ «គ្រប់» របស់វាមិនរាប់ ledger។
3. ⛔ **«តើ *អ្នកណាខ្លះ* ប្រើធនធានចែករំលែកនេះ?»** — កែផ្លូវ ១ មិនចប់
4. ⛔ **«តើលេខនេះមានអត្តសញ្ញាណទេ?»** — counter គ្មានអត្តសញ្ញាណ ជាប្រភពនៃ
   ថ្នាក់ដែលវិលមកតាមទ្វារផ្សេងៗ
5. ⛔ **«តើលេខតែមួយនេះ ត្រូវបានគណនានៅ *កម្រិត* ណា?»** (មើល (ឃ))
6. ⛔ **«តើលេខនេះមាន *សិទ្ធិ* ត្រូវបង្ហាញទេ?»** (ថ្មី — មើល (ង))

## ជំហាន ២ — បច្ចេកទេសដែលរកឃើញកំហុសពិត (មិនមែនការអានកូដ)

### ក. តារាងប្រៀបធៀបផ្នែកបងប្អូន
ដាក់ផ្នែក ២ ដែលមាន **រូបរាងដដែល** ក្បែរគ្នា រួចសួរជួរនីមួយៗ។

### ខ. `grep` កន្លែងហៅ **ទាំងអស់** របស់ធនធានចែករំលែក
ពិនិត្យ **ម្តងមួយ** ៖ សរសេរតាម delta របស់ **សតិ** ឬតាម **សាលក្រម server**?

### គ. ដាក់ dependency ក្នុងរបៀបបរាជ័យទាំង ៤
បដិសេធ · **អវត្តមាន** (`TypeError` synchronous) · **ព្យួរ** · **យឺតតែជោគជ័យ** —
មើលតារាងក្នុង `CLAUDE.md` ផ្នែក «ការព្យួរ ≠ ការធ្លាក់»។ អនុវត្តលើ **ការដកវិញ**
ដែរ (`ledger-failed-apply-revert-test` · `emu/ledger-revert-emu-test`)។
⛔ **RTDB មិនបដិសេធពេលក្រៅបណ្តាញទេ — វា *ចាក់ជួរ*** ➜ អ្នកកេះពិតជា
`permission_denied` និង `maxretry`។

### ឃ. **កម្រិតបូក (aggregation level)** — មានអ្នកយាមរួច
`Σ_d f(x_d)` ≠ `f(Σ x_d)` ពេល `f` មិនលីនេអ៊ែរ (`Math.max` · `clamp` · `round`)។
ស្កេន ៖ រកគ្រប់ការបូកលើសំណុំ រួចសួរ «clamp នៅ **ខាងក្នុង** ឬ **ខាងក្រៅ**?»។
អ្នកយាម ៖ `stats-screen-agreement-test` (អានលេខចេញពី HTML)។

### ង. 🔴 **សិទ្ធិវាស់ (measurability)** — បច្ចេកទេសដែលរកឃើញ 2.31.7
រាល់លេខដេរីវេមានច្រកទ្វារ «វាស់បាន ➜ លេខ · វាស់មិនបាន ➜ `—`»។ **រាប់ប្រភព
របស់រូបមន្ត រួចរាប់ប្រភពដែលច្រកទ្វារពិនិត្យ — ២ លេខនេះត្រូវស្មើគ្នា** ៖
`collected = ledger − open` មានប្រភព **២** តែច្រកទ្វារធ្លាប់ពិនិត្យ **១**។
⛔ ការដកកុហក **២ ខាង** ៖ «ប្រវត្តិទទេ ➜ ចំណូល = ledger» (ធំជាងការពិត) និង
«ledger ចាស់ ➜ `max(0, ចាស់ − ថ្មី)` = **`$0.00`**» (តូចជាងការពិត) — ការសរសេរ
ច្បាប់តែទិសមួយ **ធានាថាទិសទី ២ គ្មានអ្នកយាម**។
⛔ **checker ដែលចាក់សោ *លេខ* មើលមិនឃើញទេ** (វាផ្គត់ផ្គង់ listener ជា «រស់»
ជានិច្ច) ➜ ត្រូវដាក់ listener ក្នុងរបៀប **ព្យួរ** និង **ងាប់**
(`stats-measurable-gate-test`)។

## ជំហាន ៣ — វិន័យរបស់ឧបករណ៍ (⛔ ឧបករណ៍មុន ➜ ទើបកែកូដ)

**រកឃើញកំហុស ➜ សាង checker ជាមុន ➜ បញ្ជាក់ថាវាធ្លាក់លើ `origin/main` ➜ ទើបកែកូដ។**

```bash
rm -rf /tmp/baseline && mkdir /tmp/baseline
git fetch origin main && git archive origin/main | tar -x -C /tmp/baseline
<CHECKER>_APP_DIR=/tmp/baseline node audit-tools/<checker>.js   # ត្រូវធ្លាក់!
mkdir -p /tmp/emptytree && <CHECKER>_APP_DIR=/tmp/emptytree node audit-tools/<checker>.js  # ត្រូវធ្លាក់ដែរ!
```

- បើតេស្តថ្មី**ជោគជ័យ**លើ tree មុនកែ ➜ វាមិនចាប់អ្វីទេ ➜ សរសេរឡើងវិញ
- ⛔ checker ថ្មីត្រូវ ៖ មាន `*_APP_DIR` · ចុះឈ្មោះក្នុង `run-all.sh`
  **ទាំង ២ កន្លែង** (ការរត់ធម្មតា **និង** ផ្នែក baseline) · ធ្លាក់លើថតទទេ ·
  មាន **ជាន់អប្បបរមា** និង **probe ទិសផ្ទុយ** · exit code ១ ពិត
- ⛔ រកឈ្មោះ function មិនឃើញ ➜ **stub** មិនមែន `process.exit` (បើអត់
  ការអះអាងខាងក្រោមត្រូវបិទបាំង)
- ⛔ កុំសាង checker ស្ទួន — សាកឧបករណ៍ចាស់ជាមុនសិន
- ⚠️ helper ថ្មីធ្វើឲ្យ sandbox បាក់ (`ReferenceError`) ជា **សញ្ញាល្អ**
- ⛔ ក្រោយសាង checker ថ្មី ត្រូវរត់ `checker-coverage.js` ជាមុន — វាចាក់សោ
  ថា checker ថ្មីនោះពិតជាមើលកូដ

🔴 **ពេល mutation រស់រានលើ *ម្ចាស់ច្បាប់* នោះជាសញ្ញាថាច្បាប់សរសេរខ្លីពេក។**
វាស់បាន (2.31.7) ៖ mutation ដែលឲ្យ error callback របស់ listener មួយបញ្ជូន
**កូនសោបងប្អូន** រស់រានលើ checker **១៥៨ ទាំងអស់** — រួម `listener-pending-key-test`
ដែលជាម្ចាស់ច្បាប់ «កូនសោដែលសួរ ↔ កូនសោដែលដាក់ចូល»។ ច្បាប់ដើមទាមទារតែថាកូនសោ
**មាន** ក្នុង `Set`។ ⛔ ដំណោះស្រាយ ៖ **ពង្រីកឧបករណ៍ដើម** (ច្បាប់ ១២) មិនមែន
សាង checker ថ្មី។

🔴 **ពេល mutation មួយ *រស់រាន*** ៖ សួរ «តើវា equivalent ដោយសារ **សាខានោះជា
កូដងាប់** ឬ?» ➜ បើមែន ⛔ **លុបសាខានោះចេញ** មិនមែនសរសេរ assertion ក្លែងទេ។

⛔ **តម្លៃសាកល្បងជា *លេខមូល* លាក់ mutation នៃការបង្គត់** (2.31.6) ➜ ត្រូវមាន
សេណារីយ៉ូ **ដែលចម្លើយមានសេន**។
⛔ **allowlist មិនវាស់ថាកូដនោះ *រស់*** (2.31.6 ៖ ៧/១៥ បន្ទាត់ជាកូដងាប់) ➜
